## Порядок работы в каждой итерации

1. Прочитать `docs/STATUS.md`, `docs/DECISIONS.md`, `docs/ARCHITECTURE.md`, `docs/SPEC.md`.
2. Восстановить стенд (`docs/TESTING.md`): `install` **отвязанным** процессом
   (`setsid nohup bash wp-dev/stand.sh install </dev/null >/tmp/stand-install.log 2>&1 &`),
   затем `up` для `main` и `min`. **Не запускать `stand.sh up` в foreground tool-вызове — это демон.**
3. Писать код по правилам безопасности из `docs/ARCHITECTURE.md`.
4. Прогонять по **отдельности** (одна длинная команда упирается в лимит времени):
   `check.sh static`, `tests main`, `tests min`, `stand main`, `stand min`, `pcp`, при необходимости `cache`.
   При правках форматирования — `phpcbf --standard=wp-dev/phpcs.xml.dist`.
5. Поднять версию в **трёх** местах (заголовок плагина, `RVN_COMPARE_VERSION`, `Stable tag`),
   собрать ZIP (`wp-dev/build-zip.sh` или `zip` вручную), отчёт в `docs/test-reports/<версия>.md`.
6. Обновить `CHANGELOG.md`, Changelog в `readme.txt`, этот файл, `src/data/answer.ts`.

## Открытые задачи прямо сейчас (итерация 3 / 0.4.0)

### Обязательно до «готово»

1. Прогнать `check.sh static` — WPCS, PHPStan, синтаксис 8.1–8.4, точки входа на 7.0, переводы.
2. Прогнать `wp-dev/tests/core-logic.php` и `rest-smoke.py`; теперь они включают базовую проверку `/table`.
3. `check.sh stand main` и `stand min` (main = Storefront; min = WP 6.4.7 + WC 8.2 + PHP 8.1 + ru_RU).
4. `check.sh pcp` — Plugin Check 0 errors / 0 warnings.
5. `check.sh cache` — WP Super Cache: список и таблица поверх закэшированной страницы, nonce recovery.
6. `check.sh table main` и `table min` — браузерный smoke с временной статической страницей и скриншотом.
7. Ручной чек-лист таблицы (см. `docs/TESTING.md` § «Ручной чек-лист 0.4.0»).
8. Русские строки таблицы: все новые `__()` / `_e()` должны быть в `wp-dev/i18n/ru_RU.json`, затем `bash wp-dev/i18n.sh`.
9. Запись 0.4.0 в `CHANGELOG.md` и `readme.txt` Changelog + обновлённое короткое описание.
10. `docs/test-reports/0.4.0.md` + обновление ARCHITECTURE/STATUS.
11. Ключи `uninstall.php`: уже есть `rvn_compare_page_id` и `rvn_compare_page_backup` — подтвердить, что новых опций сверх этого нет.

### Риски, на которые смотреть в первую очередь

- Таблица строится JS-ом через REST: в HTML из кэша **нет** персональных ID — это правильно, но нужно убедиться, что `table.js` реально подключается на странице сравнения и на страницах с шорткодом.
- `Table_View` / `table.js` обещают не вставлять названия через `innerHTML` — проверить, что все пользовательские строки идут через `textContent` / `el()`.
- `Comparison_Page::ensure()` не должна затирать чужую страницу со slug `compare`.
- `append_table` + шорткод не должны давать **двойной** вывод таблицы.
- Бренд (`product_brand`) появляется в registry только если таксономия существует — на старых WC без брендов не должен ломаться.
- Колонки / breakpoints: `breakpoint_phone < breakpoint_tablet` enforced в sanitize.
- Новые строки без перевода ru_RU — частая причина провала `check.sh static` на i18n.
